# Local publications workflow

The Publications page reads only `_data/publications.json`. That file is
generated from reviewed records by `python3 script/publications.py build`.
Discovery never puts a paper on the site. This workflow is local only: do not
schedule it, push, open a PR, merge, or deploy without the website maintainer's
explicit authorization and the required scientific review.

For a routine local update:

```sh
make publications-update   # OpenAlex and configured arXiv sources; candidates only
make publications-review   # work counts and 25 pending candidates
# Review each paper and record an approval or exclusion (section 4).
make publications-build    # approved records only; run after review
make check
```

`make publications-update` defaults to `discover --no-crossref`, so it needs no
contact email. To enrich new DOI records with Crossref, set a real contact
email and run `make publications-update PUBLICATIONS_DISCOVER_FLAGS=`. For a
single DOI, `python3 script/publications.py verify-doi '<candidate-id>'` checks
Crossref without rebuilding the site. `PUBLICATIONS_LIST_LIMIT=50` changes how
many pending records `make publications-review` shows. These commands use the
verified identifiers in the review configuration; they do not discover every
paper by a member with an unverified name search.

## Files and ownership

| File | Purpose | Editing rule |
| --- | --- | --- |
| `_publication_review/researchers.json` | Verified OpenAlex author profiles for the PI and current/former members | Edit after identity verification |
| `_publication_review/arxiv_sources.json` | Known arXiv IDs and optional reviewed author searches | Add only with a verified researcher and source URL |
| `_publication_review/candidates.json` | OpenAlex and arXiv version records, enriched where appropriate by Crossref | Script-managed; do not use as the public bibliography |
| `_publication_review/decisions.json` | Approval/exclusion, reviewed type, evidence, and editorial corrections | Edit corrections here; `approve`/`exclude` manage status |
| `_publication_review/manual.json` | Exceptional papers not found through configured profiles | Add through `add` or edit carefully; still requires approval |
| `_publication_review/works.json` | Stable work IDs, version IDs, evidence for confirmed matches, and preserved website card IDs | Generated by `sync-works`; use `link-versions` for manual confirmations |
| `_publication_review/possible_matches.json` | Similar records that need manual version review | Generated; suggestions never merge records |
| `_publication_review/rejected_matches.json` | Reviewed pairs known to be different works | Generated by `reject-match` when needed |
| `_data/publications.json` | Approved, sorted records for Jekyll | Generated by `build`; do not edit by hand |

All review files are under a Jekyll underscore directory and are not
published as website pages. They may contain public bibliographic metadata for
papers that do **not** belong on the AutoDIAL site; only approved records are
rendered. The 2026-11-21 local refresh has 189 deduplicated candidates in 184
work groups from Prof. Jason Hattrick-Simpers's verified OpenAlex profile and
configured arXiv IDs. Seventeen journal versions and five arXiv preprint
versions have passed a local source review for the redesign preview; 167 candidates remain
pending. The journal DOIs were checked against their source records, while
arXiv-only preprints do not require Crossref. AutoREC's approved journal and
preprint versions display as one work, so the website has 21 entries.
These editorial decisions are **not PI
approval**; the entire redesign remains local.

## 1. Verify researcher identities

For each researcher, inspect their OpenAlex author profile and several listed
works against an ORCID record, institutional profile, CV, or another reliable
source. Check for namesakes or split author profiles. Record each verified
profile as an object in `researchers.json`:

| Field | Required value |
| --- | --- |
| `name` | Display name for the review log |
| `relationship` | `pi`, `current`, or `former` |
| `openalex_author_id` | Verified OpenAlex `A` identifier, with no URL prefix |
| `orcid` | Verified ORCID when available; the script checks it against OpenAlex |
| `verification_url` | HTTPS link used to confirm identity |
| `verified` | `true` only after checking independent identity evidence |
| `verified_by` | Person or tool that checked the profile, with date |

The PI's `A5073635313` profile is recorded with ORCID
`0000-0003-2937-3188`. OpenAlex reports the PI's name and ORCID; the public
ORCID record names Jason Hattrick-Simpers, and the [University of Toronto
faculty profile](https://mse.utoronto.ca/faculty-staff/professors/jason-hattrick-simpers/)
identifies him with AutoDIAL. The `verification_sources` array preserves the
profile links. For additional current or former members, add a verified object
to `researchers.json`; do not use name searches as a substitute for a verified
identifier. The script checks that each OpenAlex profile resolves and, when
provided, that its ORCID matches. Profile matching does not establish whether
an individual paper belongs to AutoDIAL.

OpenAlex documents [author IDs](https://help.openalex.org/data/authors/),
[ORCID matching](https://help.openalex.org/data/authors/orcid/), and
[author work filters](https://help.openalex.org/how-to/api-recipes/).

## 2. Discover and inspect candidates

The direct script command for an OpenAlex-only refresh leaves newly found
records pending; the Make target above also refreshes configured arXiv IDs:

```sh
python3 script/publications.py discover --no-crossref
python3 script/publications.py list --year 2025 --limit 25
python3 script/publications.py list --status approved
```

`list` is newest first and can also filter with `--status pending`,
`--status excluded`, or `--all`. The candidate JSON retains all fields and
metadata warnings for detailed review. To check one DOI against Crossref:

```sh
python3 script/publications.py verify-doi '<candidate-id>'
```

For bulk Crossref enrichment, provide a **real contact email you are
authorized to use** for Crossref's polite pool, and keep any OpenAlex key in
the environment, never in Git:

```sh
export PUBLICATIONS_CONTACT_EMAIL='your-real-contact@example.org'
export OPENALEX_API_KEY='your-private-key' # optional for ordinary paging
python3 script/publications.py discover
```

Those values are placeholders. The OpenAlex key becomes necessary if an author
exceeds its 10,000-result basic paging limit. The script uses 100 results per
page, follows cursor pages when a key is present, and stops without replacing
candidate data if an API request fails. It retries temporary failures and
`429` responses with backoff. Crossref fills missing fields and flags title/year
disagreement; a Crossref `404` does not automatically exclude a paper. Results
are cached for 30 days; use `discover --refresh-crossref` when a deposit has
been corrected. The 2026-11-14 initial import used `--no-crossref`; selected
journal and repository DOIs were subsequently checked individually. An
arXiv-only preprint does **not** need Crossref verification.

Official API references: [OpenAlex paging](https://help.openalex.org/api/paging/),
[OpenAlex authentication and limits](https://help.openalex.org/api/authentication/),
[Crossref REST tips](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/), and
[Crossref rate-limit guidance](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/).

### arXiv discovery and identity review

Add exact IDs to `arxiv_sources.json` under `known_ids`. Each item needs
`arxiv_id`, the exact `researcher` name already verified in `researchers.json`,
an HTTPS `verification_url`, and `verified_by`. The configured IDs include
`2604.27266` (AutoREC), `2607.19307` (the EIS measurement preprint),
`2609.22411` (AutoRASOR), `2605.05104` (Diversity-Aware Active Learning), and
`2512.01080` (Building Trustworthy AI). To
search by author name, add an `author_searches` entry with `name`,
`researcher`, `verification_url`, `verified_by`, and a bounded `max_results`.
The name must match an author in each returned arXiv record. A name match is
**not** identity proof: every arXiv result remains `identity_status:
needs_review` until a reviewer checks the actual paper and independent author
evidence. Search results stay pending and are never published automatically.

```sh
python3 script/publications.py discover-arxiv
python3 script/publications.py list --status pending --year 2026
```

arXiv IDs and URLs are normalized to a version-free `arxiv:<id>` alias and an
HTTPS `/abs/<id>` link. The latest API revision number is recorded in
`arxiv_versions`; later imports retain prior observed revisions. The arXiv DOI
`10.48550/arxiv.<id>` identifies the preprint version. An optional publisher
DOI in arXiv metadata is recorded as a version relationship, never substituted
for the preprint DOI. The importer follows arXiv pagination up to the
configured limit and leaves the candidate file unchanged if an API or identity
check fails. [arXiv's API manual](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md)
documents `id_list`, author search, Atom metadata, and versioned IDs.

## 3. Match versions into stable works

Run `python3 script/publications.py sync-works` after editing manual records
or relationship evidence. Discovery and DOI verification run it automatically.
`works.json` gives every scientific work a stable `work-...` ID and a
`site_id`; the initial migration retained the existing 16 website card IDs.
Candidate/version IDs and every existing entry in `decisions.json` remain
unchanged. A later journal DOI joins the same work without changing its work
ID or website anchor. If two already approved works are linked, the command
requires `--keep-work` so the site ID choice is explicit.

The script confirms a relationship only from shared OpenAlex work identity,
an explicit arXiv publisher DOI or Crossref preprint/version relation, or
the same ChemRxiv manuscript stem across numbered revisions. Crossref uses
[`is-preprint-of` and `has-preprint`](https://www.crossref.org/documentation/schema-library/markup-guide-record-types/posted-content-includes-preprints/)
for preprint–journal links. Similar title, overlapping authors, and nearby
years produce an entry in `possible_matches.json` for review; they never
merge records by themselves.

For a confirmed pair without a deposited relationship, inspect both original
sources and record the evidence in a manual link decision:

```sh
python3 script/publications.py link-versions '<preprint-id>' '<journal-id>' \
  --reviewer '<reviewer>' --note '<specific source links and matching evidence>'
python3 script/publications.py reject-match '<first-id>' '<second-id>' \
  --note '<why these similar titles describe different work>'
python3 script/publications.py report
```

The Cantor alloy SSRN preprint and 2026 journal article were manually linked
after checking the source records; Crossref currently deposits no relationship
between them. ChemRxiv revisions 2–4 of *Roadmap on Data-Centric Materials
Science* share a manuscript stem and a Crossref `has-version` relation. Its
journal article was linked after a manual source check. All six version records
remain unapproved as AutoDIAL site content. Their version relationship stays
in review data even when a journal DOI becomes the only reader-facing link.

## 4. Review each publication

For each candidate, check the actual paper, author list, venue, year, DOI,
publication type, and whether the work belongs to AutoDIAL. A former member's
unrelated work must not appear merely because it shares an author profile.
OpenAlex and Crossref types are only suggestions; the reviewer must explicitly
choose `journal`, `preprint`, or `other`. Review and link versions of the same
work rather than approving them as two site entries. Resolve any
`metadata_warnings` before approval. For an arXiv preprint, supply independent
author identity evidence; no Crossref lookup is required.

```sh
python3 script/publications.py approve '<candidate-id>' \
  --type journal --reviewer '<reviewer>' \
  --note '<evidence that this paper belongs on the site>'
python3 script/publications.py approve 'doi:10.48550/arxiv.<id>' \
  --type preprint --reviewer '<reviewer>' \
  --identity-evidence '<institutional profile or author confirmation>' \
  --note '<evidence that this preprint belongs on the site>'
python3 script/publications.py exclude '<candidate-id>' \
  --note '<reason for exclusion>'
```

IDs come from `list`; DOI-backed records use `doi:...`. Approval requires a
reviewer and evidence note. The commands preserve existing `overrides` in
`decisions.json`. To correct metadata or add editorial material, edit only the
approved decision's `overrides` object. Supported fields are `title`,
`authors` (array), `venue`, `year`, `doi`, `landing_page_url`, `software_url`,
`dataset_url`, `extra_links` (array of `{ "label", "url" }`), and `image`.
An image object uses `src` under `/assets/images/`, `alt`, `width`, `height`,
and optional `caption`. Link URLs must use HTTPS. A DOI or reviewed publication
link is required before a record can be built. Editorial overrides survive
subsequent discovery runs because discovery never edits decisions.
For the AutoEIS demonstration, the decision records a local source review and
corrects the OpenAlex author/venue display to the [JOSS article](https://joss.theoj.org/papers/10.21105/joss.06256)
and Crossref record; it also links the existing AutoEIS documentation. All
sixteen local selections need PI review before release. Evidence URLs and
reasons are recorded per DOI in `decisions.json`.

```sh
python3 script/publications.py add --id 'manual:<short-slug>' \
  --title '<verified title>' --author '<first author>' \

  --year 2025 --url 'https://<verified-publication-page>'
```

Replace every placeholder before running the command. You can omit `--id`
when `--doi` is provided. If a manually added DOI later appears in OpenAlex,
the workflow merges the records by identifier and keeps the editorial decision.

## 5. Build and review the local site

```sh
make publications-build
make check
make test
```

`build` writes one entry per work with at least one approved version, newest
year first. A verified journal version becomes primary only after its own
approval; until then, an approved preprint retains its citation and year. A
journal entry with a DOI uses that DOI as its paper link; it does not show a
second preprint link. The matching preprint and its approvals, overrides, and
review notes remain in the review data. A preprint-only entry is labeled
`Preprint` and uses its DOI or HTTPS repository page as its paper link, without
duplicating an arXiv DOI as an `arXiv preprint` link. `build` fails without
replacing the previous public data if an approved decision loses its source
record or lacks required metadata. The Jekyll page groups by year and provides
browser-side title/author/venue search plus year/type filters. With JavaScript
off, all approved entries remain visible. With no approved entries, the page
shows a neutral review message. Review the rendered page on desktop and phone
widths, including links, image captions, keyboard controls, and scientific
accuracy. The site and this workflow remain local until separately approved.
